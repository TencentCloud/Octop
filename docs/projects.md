# 项目模式设计

项目是一种专家。它自己完成任务，需要时把别的专家当作工具调用。任务是这个项目下的对话。能打开项目的人看到全部任务，并可以继续问。

本文是设计，尚未实现。专家上的「共享会话」已经单独落地：会话默认私有，主人可以再把某一条开放出去。那不是项目。

## 区别和联系

专家、团队、项目都是 `agents` 里的一行。工作区、记忆、对话都挂在这一行上。差别在谁干活、别人怎么进来、上下文怎么带。

| | 专家 `kind=expert` | 团队 `kind=team` | 项目 `kind=project` |
|---|---|---|---|
| 是什么 | 一个人可用的专家 | 主持人加至少两名成员 | 一块共享的工作，本身也是专家 |
| 谁干活 | 自己 | 主持人只调度，成员干活 | 自己做完；需要时再调用专家 |
| 工具 | 干活的全套，含技能 | 只有 `agent_list`、异步 `ask_agent`、记忆、时间 | 和专家同一套 |
| 调用专家 | 可以同步调用 | 异步派工，编制写在 `.octop/manifest.json` | 同步调用，名单写在项目配置里，可以为空 |
| 谁能打开 | 仅自己、全部或指定分组 | 当前不能分享，只有创建者 | 和专家一样：仅自己、全部或指定分组 |
| 对话谁能看 | 默认只有自己；主人可再共享某一条 | 只有创建者 | 能打开项目的人看到全部任务 |
| 知识库、连接器 | 选进专家的，按当前发消息的人再滤一遍 | 主持人不挂 | 项目默认按主人调用；对话里另选的按当前用户的授权 |
| 技能 | 挂在专家上，主人管理 | 主持人不挂技能 | 和专家一样，挂在项目上 |
| 制品 | 专家工作区 | 各写各的工作区 | 项目工作区 |

联系：

- 项目和专家共用同一套技能、知识库、连接器、工作区和记忆。团队主持人是调度壳，这些能力在成员专家上。
- 三者的准入都不是点名用户。专家和项目用「仅自己 / 全部 / 指定分组」。团队仍保持不分享。
- 任务不另建表。专家的会话、团队房间、项目任务都是 `threads`。
- 可调用的专家仍是普通专家。项目调用他们是一次工具返回，不是团队那种上墙派工。

## 谁能用

创建和编辑项目时选择可见范围，复用专家现在的「仅自己 / 全部 / 指定分组」。不单独点名用户。

被选中的人可以打开项目、看到全部任务、继续追问、处理待审批。改名称、可见范围、默认知识库、默认连接器、技能和可调用专家，只有主人可以。

## 知识库和连接器

分成两层。

项目上选中的默认知识库和默认连接器，每次任务都带上，按项目主人的身份调用。别人不用先拥有这些资源，也不会在自己的列表里看到它们，不能拿到别的专家上用。凭证仍是主人的，只在这个项目里生效。对话里不能拿掉这层默认。

发消息时还可以再选。可选的只包括当前这个人自己的，以及别人已经共享给他的。这一层按该用户自己的授权调用，加在项目默认之上。

因此一次任务里可以同时有两套：项目默认走主人，对话里勾上的走当前用户。

今天的专家还不是这样。别人发消息时，专家上选的知识库和连接器会按这个人自己的可见范围再滤一遍。项目按上面的两层做。专家是否改成同样的默认层，不在这一版里。

## 技能

技能跟专家一样管理：挂在这个项目上，主人启用或停用。谁来聊都用这一份，不按用户再授权一次。

## 任务

一条任务就是这个项目下的一条对话。能打开项目的人默认都能看见，不必再逐条点共享。

状态从这一轮运行情况读出来，不另做工单：

- **进行中**：这一轮还在跑。有人追问后，从已完成回到进行中。
- **待审批**：停在工具确认上。能看这条任务的人都可以处理。
- **已完成**：这一轮正常结束。
- **失败**：这一轮出错结束。现有接口若还没有失败标记，第一版先不画这个图标。

创建人记在对话上。改名、置顶、删除、分叉，以及模型和审批设置，只有创建人可以。其他人可以发消息。调用专家产生的内部会话不出现在任务列表里。

记忆是这个项目专家的一份，房间里的人共用。按人隔开放到后面。

## 页面

左侧导航增加「项目」，路径 `/projects`。

列表是卡片：名称、简介、进行中和待审批的数量。主人可以新建、编辑、删除。

详情列出当前绑定，主人可改，其他人只读：

- 知识库
- 连接器
- 技能
- 可调用的专家

页头有「打开任务」，进入聊天里的这个项目。

聊天侧栏的分页改为「专家 / 团队 / 项目」，用「项目」换掉「云端」。对端专家仍在「专家」里，对端团队仍在「团队」里，云端协同页面留在原入口。

「项目」下展开的是任务。进行中和待审批排在前面，可筛「全部 / 进行中 / 待审批」。按钮写「新任务」。每一行有标题、状态、发起人头像，名字在悬停时出现。

任务页仍是现在的聊天。顶栏标「项目」，下面一行只读摘要链到项目详情。制品在右侧文件栏，读这个项目的工作区。

## 实现时沿用的结构

不新建项目表，也不新建任务表。

- `agents.kind` 增加 `project`。现在只接受 `expert` 和 `team`。
- 可调用专家写在该专家配置里的一份 id 列表，不用团队清单。
- 运行时走专家装配，不套主持人的工具白名单。`ask_agent` 用专家现有的同步调用，名单之外的专家调不到；名单为空就不提供这项工具。
- 项目线程对能打开该项目的人全部可见。追问、作者和待审批走已经做好的共享会话路径。共享专家上的逐条共享保持不变。
- `TEAM_NOT_SHAREABLE` 继续只拦团队。

## 不做

- 不把项目做成共享团队，不放开团队分享。
- 不点名用户，不用第二张成员表。
- 不做看板、项目动态、关闭后锁定的工单。
- 不把项目默认的知识库和连接器复制进每个用户自己的库。
