## 二、未闭合 / 部分闭合明细（重点）

### 二.1 B1（部分闭合）——附录 F 有 5 个文件目录写错

数字口径本身已统一（16 处 / 8 文件），但**附录 F 的 5 个文件路径目录写错**，照此执行会找不到文件：

| #12 | `tests/unit/agents/test_agent_profile_columns.py` | `tests/unit/db/test_agent_profile_columns.py` |

| #15 | `tests/unit/skills/test_skill_packages_repo.py` | `tests/unit/db/test_skill_packages_repo.py` |

（#1–#7 `tests/unit/db/test_db_pool.py`、#8/#9 `tests/unit/backup/test_system_archive.py`、#16 `tests/unit/db/test_repo_knowledge.py` 正确。）

**证据（文档内）**：附录 C 写的是「`tests/unit/db/test_db_pool.py` + 另 7 个测试文件（16 处）」，即 8 个文件同处 `tests/unit/db/`（除 backup），与附录 F 把其中 5 个散落到 `skills/`/`agents/`/`gateway/`/`experts/` 相矛盾。
**影响**：T1.2 / 附录 D 都叫开发者「照附录 F 逐文件改」，路径错 5 处 → 第一天照做会找不到文件卡住。
**修法**：把附录 F 的 5 个路径改回 `tests/unit/db/`。

### 二.2 H8（部分闭合）——工期阶段小计未随任务卡再估同步

### 二.3 M10（部分闭合）——「KB 成员授权」未显式写出

§2.2 把「跨用户协作」整体后置到 M2 S4，但审查发现的具体缺口是「M3 绑定项目知识库（KB 成员）——`knowledge_base_members` 表在 v7 已被 DROP，需重建」。v2.0 全文**没有任何一处**显式提到「KB 成员授权模型」或「重建 knowledge_base_members」：
