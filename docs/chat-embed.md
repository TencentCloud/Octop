# 嵌入单个 Agent 的聊天页面

使用 `/embed/chat/{agentId}` 在业务系统的 iframe 中显示聊天页面；指定会话时使用
`/embed/chat/{agentId}/{threadId}`。页面不显示控制台导航、会话侧栏或专家切换入口。
进入未指定会话的地址时，会沿用当前用户在该 Agent 下的首选会话；输入框可以新建会话。

```html
<iframe
  src="https://octop.example.com/embed/chat/AGENT_ID"
  title="AI 助手"
  allow="microphone"
  style="width: 100%; height: 480px; border: 0"
></iframe>
```

将示例域名和 `AGENT_ID` 替换为实际部署地址和 Agent ID。

部署地址必须能被业务系统用户的浏览器访问。Octop 默认监听 `127.0.0.1:8088`，
其他机器无法直接连接该回环地址；可通过反向代理提供上述 HTTPS 地址，或用
`octop run --host 0.0.0.0 --port 8088` 提供局域网访问。配置项和环境变量见
[配置说明](configuration.md)。本功能不改变服务的默认监听地址。

语音输入需要 HTTPS（本机 localhost 调试除外）和用户授予麦克风权限。跨源 iframe
还需要示例中的 `allow="microphone"`；宿主页的 `Permissions-Policy` 响应头也必须允许
Octop 来源，iframe 的 `allow` 不能覆盖宿主页明确禁止的策略。浏览器明确报告麦克风
被宿主策略禁止时，语音按钮会禁用并说明原因。

嵌入页面沿用 Octop 登录及现有 Agent、会话访问检查。未登录或登录过期时，页面进入
登录流程，并在登录成功后返回原嵌入地址。跨站 iframe 需要在其自身的浏览器存储环境中
登录；本功能不提供业务系统会话换取 Octop 票据的免登录能力，也不缩小现有用户凭证的权限。

聊天发送、流式回复、停止生成、附件、工具审批和问题回答继续使用现有聊天流程。
目标 Agent 不存在或当前用户无权访问时，页面不会切换到其他 Agent。
Agent 未就绪时，页面沿用现有的每 10 秒状态刷新；运维在控制台修复后，嵌入页会根据
恢复的 Agent 状态重新显示聊天，无需新增管理入口。
渲染错误后的返回按钮会回到当前 Agent 的嵌入入口；畸形嵌入地址显示无壳 404，
缺少 Agent ID 时不显示返回控制台的按钮。

2026-10-03 使用 Edge 154.0.4258.48，在跨源 iframe 中加载实际 App 和聊天组件，

使用模拟传输；本次验收覆盖页面交互与布局，不包含真实模型回复或语音识别。

问题卡片最多占嵌入聊天区域的一半高度，超出部分在卡片区域内滚动，保留输入框操作空间。
