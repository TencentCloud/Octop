# Agent Mail CLI 连接器

Agent Mail 为 Agent 提供独立邮箱。本连接器通过官方 `@tencent-qqmail/agently-cli`
接入，已核对 CLI 1.0.18 的命令契约。

## 配置

1. 在「连接器 → 内置连接器 → Agent Mail」中，由管理员安装主机 CLI。
2. 填写连接器名称并保存，再点「登录授权」。
3. 打开抽屉提供的官方授权页完成登录；抽屉自动更新授权状态，也可手动检查。
4. 探测成功后，在 Agent 的连接器选择中绑定该实例。

每个实例使用独立的 CLI 原生 workspace（同时隔离配置与 keychain 命名空间）。不同 Agent 需要不同邮箱时，分别创建实例并授权。
同一实例被显式共享或绑定到多个 Agent 时，这些 Agent 使用同一个邮箱。
OAuth 凭据由官方 CLI 管理；Octop 不向 Dashboard 或模型返回访问令牌。
登录流程在后台运行，超时、取消、删除实例和服务关闭时清理子进程。

授权页还支持刷新、注销。注销会清除 CLI 授权并尝试撤销远端凭据。
删除实例会注销 CLI 凭据并清理 Octop 内的暂存附件。

CLI 1.0.18 设置 `AGENTLY_CLI_CONFIG_DIR` 后会强制使用 `default` workspace，
而 keychain 不跟随该目录。本连接器清除继承的 `AGENTLY_*` 变量，只设置由实例
路径哈希生成的唯一 `AGENTLY_WORKSPACE`，不使用 `AGENTLY_CLI_CONFIG_DIR`。

## 工具与确认

提供身份/配额、邮件列表、读取、搜索、发送、回复、转发、移入已删除、永久删除，
以及附件上传/下载。登录、注销和刷新在配置页操作，不作为模型工具。
新邮件通过后台 `message +watch` 长连接触发任务，不调用模型轮询邮箱。

发送、回复、转发及两种删除操作统一由网关执行两阶段确认。CLI 1.0.18 的上游确认是条件性的，
单封永久删除可能直接执行，因此不能把首次实际写请求用作预览：

1. 首次调用仅运行 CLI `--dry-run` 校验参数，返回 `confirmation_required`、`confirmation_token` 和摘要，尚未执行写操作。
2. 带 `confirmation_token` 的第二次调用会走 Octop 现有 HITL 工具审批；用户批准后网关才消费令牌并真正写入。
3. 令牌绑定实例、工具和原参数，五分钟内有效且只能使用一次；过期未用文件会在下次预览时清理。
4. 若上游另要求确认，网关在已经获得用户确认的同一次调用内，使用上游令牌及相同参数完成操作。

网关拒绝 `confirmed`、原始命令行参数、`body_file` 等未公开字段。
Cron 与新邮件任务禁止发送、回复、转发和删除，即使模型拿到令牌也不会执行。
安装 CLI 时钉死 `@tencent-qqmail/agently-cli@1.0.18`。
邮件正文、邮件头、附件名及其他上游内容均包裹为不可信外部数据，不能作为指令执行。

收件人字段接受逗号分隔的邮箱地址。附件上传接受 `filename` 与 `content_base64`，
下载返回 `content_base64` 及实例内文件标识 `file`。发送/回复/转发的 `attachments`
字段填写这些文件标识，每行一个，确认时原样复用。工具不能指定任意主机文件路径。
暂存文件保留到删除连接器实例；不写入 Agent 工作区。

## 新邮件触发任务

在「任务 → 创建任务」的触发方式中选择「Agent Mail 新邮件」，选择已授权的邮箱，
填写任务内容并启用。选择 Agent 任务时，只在收到新邮件后调用模型；纯文本任务直接发送通知。
任务继承现有的模型选择、对话路由、执行记录和通知，自动加载事件来源邮箱的连接器。
API / Cron 工具的触发值为 `agently:<instance_id>`。

同一邮箱的多个任务共享一个监听进程。停用或删除最后一个任务、删除/停用连接器、服务关闭时，
回收监听进程；服务启动和任务恢复时重新订阅。CLI 负责网络重试，终止后每 60 秒尝试重启。
事件只向任务传递校验后的邮件 ID，不把邮件正文当作任务指令。未授权邮箱不能创建或调度监听任务。
任意其他连接器变更不会重启全部邮箱监听。
监听期间缓存最近 4096 个邮件 ID 去重；不保证跨服务重启去重，也不补发断网/休眠期间的邮件。

## 配额与验证边界

参考配额为每日发信 50 封、每小时 200 次请求、每分钟 10 次请求，单封最多 50 个附件、
总大小 20 MB；本连接器单附件上限 10 MB。以 `agently_me` 返回的账户限制及服务最新规则为准。

本地自动化覆盖命令参数、两阶段确认、实例隔离、附件路径边界、设备码进程生命周期、
授权 API 权限及配置页交互。真实 CLI 的无登录状态、参数 dry-run 和设备码链接输出可以独立验证。
真实账号登录后的收发邮件、令牌刷新、服务端确认令牌校验与多账号 keychain 隔离仍需授权账号验证。
