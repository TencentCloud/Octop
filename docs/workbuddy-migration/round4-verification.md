# 第四轮：组件边界与功能保留检查

本轮修复已验证的问题，保留 WorkBuddy 5.5.6 外观基准和 Octop 业务链路。**不能据此宣称全部组件、全部交互状态及全部业务操作已经无损验收。** 未提交、推送、发布，未删除 legacy 或临时展示开关。

## 本轮修复

| 编号 | 问题与影响 | 修正与证据 |
|---|---|---|
| R4-01 | 设置覆盖首页/聊天时，地址栏变为 settings，侧栏错误地追加一份历史列表，产生重复列表和额外滚动 | 侧栏根据实际背景工作区确定历史所有权；首页/会话/市场背景分别有回归测试 |

| R4-03 | 联合菜单使用受控打开状态，选择菜单项后可能继续悬浮在新页面 | 菜单选择显式关闭，再执行原导航回调；补充状态断言 |

| R4-05 | 会话“展开更多”引用未恢复的样式，显示为浏览器默认按钮 | 改为已提取的5.5.6按钮类，分页回调保持不变 |

| R4-11 | 自动化长表单把保存/取消放在全部字段之后，窗口初始状态看不到主要操作 | WorkBuddy模式将动作放入固定底栏，表单单独滚动；legacy保留行内位置；两种模式均验证校验与原onSubmit只调用一次 |

新代码集中在对应生产组件，未加入原版私有客户端或改写后端。浮层容器只负责展示生命周期，不拥有业务状态。

## 工程检查

最终结果与构建校验值记录在 `evidence/round4/engineering-checks.json`、`build-manifest.json`。

- 前端两种展示模式：各236个测试文件、1209项通过。
- `npx tsc -b` 通过；`npm run lint` 无错误、67项既有警告。
- `UV_NO_SYNC=1 make all`：格式、Ruff、mypy通过，4166 passed、17 skipped；pytest清理临时目录等警告保留在日志。
- 正式构建通过后保留两种产物，最终内置产物仍为legacy。依赖安装、前端单测、正式构建分段顺序执行，不在前端单测运行时替换依赖。
- 初次前端全测在后端并行测试负载下出现1项技能编辑测试5秒超时；没有提高超时或跳过测试。独立重跑两种完整测试均通过。
- 资源审计：10项生成资源校验通过；本轮选定修改文件的静态设计检测未报告问题。这不替代运行态视觉检查。

## 尚未覆盖的部分

1. 每个组件的所有悬停/禁用/错误/加载/长文/焦点/弹层组合，尤其复杂编辑器与多种消息工具。组件清单中未有明确证据的仍标记待验证，不能宣称“每一个组件都无问题”。
2. 扫描出的无名称按钮/开关候选仍需结合所属标签逐个核实；本轮修复了已确认的主要图标按钮，没有把所有候选自动当作缺陷或全部通过。
3. 真实普通用户与全角色、外部OAuth与渠道、实体手机/Wails、Firefox/WebKit、PWA缓存切换及Linux/Windows CI，未以本机浏览器和单测替代。
4. 所有后台有副作用操作、全部保存后重读、网络故障组合及同条件性能/内存测量，仍不具备完整验收证据。

本轮交付的是可复核的问题修复与覆盖记录；整体无损与一比一还原结论继续保留。
