## 内容概览

ASCII 艺术视频制作流程——支持任何格式。将视频/音频/图像/生成式输入转换为彩色 ASCII 字符视频输出（MP4、GIF、图像序列）。涵盖：视频转 ASCII 转换、音频反应式音乐可视化、生成式 ASCII 艺术动画、混合视频+音频反应式、文本/歌词叠加、实时终端渲染。

## 创意标准

这是视觉艺术。ASCII 字符是媒介；电影是标准。

**在编写一行代码之前**，阐明创意概念。情绪是什么？这个视频讲述了什么视觉故事？是什么让*这个*项目不同于其他所有 ASCII 视频？用户的提示是一个起点——要用创意野心去诠释它，而不是字面转录。

**首次渲染 excellence 是不可协商的。** 输出必须在不需要修改轮次的情况下在视觉上引人注目。如果某些东西看起来普通、平淡或像"AI 生成的 ASCII 艺术"，那就是错误的——在交付之前重新思考创意概念。

**超越参考词汇表。** 参考中的效果目录、着色器预设和调色板库是一个起始词汇表。对于每个项目，组合、修改并发明新模式。目录是颜料调色板——你来绘制画作。

**主动具有创意。** 当项目需要时，扩展技能的词汇表。如果参考中没有视觉需求，就构建它。至少包含一个用户没有要求但会欣赏的视觉时刻——过渡、效果、提升整个作品的色彩选择。

** cohesive 美学优于技术正确性。** 视频中的所有场景必须通过统一的视觉语言连接起来——共享色温、相关字符调色板、一致的运动词汇。一个技术正确但每个场景使用随机不同效果的视频是美学失败。

**密集、分层、经过深思熟虑。** 每一帧都应该值得观看。绝不要平淡的黑色背景。始终多网格构图。始终每个场景都有变化。始终有意的色彩。

| 视频 I/O | ffmpeg (CLI) | 解码输入、编码输出、混合音频 |

## 流程架构

每个模式都遵循相同的 6 阶段流程：

```
INPUT → ANALYZE → SCENE_FN → TONEMAP → SHADER → ENCODE
```

1. **INPUT** — 加载/解码源素材（视频帧、音频采样、图像或无）
2. **ANALYZE** — 提取每帧特征（音频频带、视频亮度/边缘、运动向量）
3. **SCENE_FN** — 场景函数渲染到像素画布 (`uint8 H,W,3`)。通过 `_render_vf()` + 像素混合模式组合多个字符网格。参见 `references/composition.md`
4. **TONEMAP** — 基于百分位的自适应亮度归一化。参见 `references/composition.md` § 自适应 Tonemap
5. **SHADER** — 通过后处理 `ShaderChain` + `FeedbackBuffer`。参见 `references/shaders.md`
6. **ENCODE** — 将原始 RGB 帧通过管道传输到 ffmpeg 以进行 H.264/GIF 编码

- **视觉一致性**：所有场景是否感觉属于同一个视频？
- **创意愿景检查**：输出是否匹配步骤 1 中的概念？如果看起来普通，返回

## 关键实现注意事项

### 亮度 — 使用 `tonemap()`，而不是线性乘数

这是 #1 视觉问题。黑色背景上的 ASCII 本质上是暗的。**绝不要使用 `canvas * N` 乘数**——它们会剪切高光。使用自适应 tonemap：

```python
def tonemap(canvas, gamma=0.75):
    f = canvas.astype(np.float32)
    lo, hi = np.percentile(f[::4, ::4], [1, 99.5])
    if hi - lo < 10:
        hi = lo + 10
    f = np.clip((f - lo) / (hi - lo), 0, 1) ** gamma
    return (f * 255).astype(np.uint8)
```

流程：`scene_fn() → tonemap() → FeedbackBuffer → ShaderChain → ffmpeg`

每段 gamma：默认 0.75，曝光过度 0.55，海报化 0.50，明亮场景 0.85。对暗层使用 `screen` 混合（不是 `overlay`）。

### 字体单元格高度

macOS Pillow：`textbbox()` 返回错误的高度。使用 `font.getmetrics()`：`cell_height = ascent + descent`。参见 `references/troubleshooting.md`。

### ffmpeg 管道死锁

绝不要对长时间运行的 ffmpeg 使用 `stderr=subprocess.PIPE`——缓冲区在 64KB 处填满并死锁。重定向到文件。参见 `references/troubleshooting.md`。

### 字体兼容性

并非所有 Unicode 字符在所有字体中都能渲染。在 init 时验证调色板——渲染每个字符，检查空白输出。参见 `references/troubleshooting.md`。

### 每段架构

对于分段视频（引用、场景、章节），将每个渲染为单独的剪辑文件以进行并行渲染和选择性重新渲染。参见 `references/scenes.md`。

## 创意分歧（仅当用户请求实验性/创意/独特输出时使用）

如果用户要求创意、实验性、令人惊讶或非传统的输出，请选择最适合的策略，并在生成代码之前通过其步骤进行推理。

- **强制连接** — 当用户想要跨域灵感时（"让它看起来有机"、"工业美学"）
- **概念混合** — 当用户命名两个要组合的事物时（"海洋遇见音乐"、"太空 + 书法"）
- **斜向策略** — 当用户最大开放时（"给我一个惊喜"、"我从未见过的东西"）

### 强制连接

1. 选择一个与视觉目标无关的域（天气系统、微生物学、建筑学、流体动力学、纺织编织）
2. 列出其核心视觉/结构元素（侵蚀 → 渐进式揭示；有丝分裂 → 分裂复制；编织 → 互锁图案）
3. 将这些元素映射到 ASCII 字符和动画模式
4. 综合——"侵蚀"或"结晶"在字符网格中看起来像什么？

### 概念混合

1. 命名两个不同的视觉/感知空间（例如，海浪 + 乐谱）
2. 映射对应关系（波峰 = 高音，波谷 = 休止，泡沫 = 断奏）
3. 选择性混合——保留最有趣的映射，丢弃强制的映射
4. 开发仅存在于混合中的新兴属性

### 斜向策略

1. 抽取一个："尊重你的错误作为隐藏意图" / "使用旧想法" / "你最接近的朋友会做什么？" / "强调缺陷" / "把它颠倒过来" / "只要一部分，而不是整体" / "反转"
2. 针对当前的 ASCII 动画挑战解释指令
3. 在编写代码之前，将横向见解应用到视觉设计中
