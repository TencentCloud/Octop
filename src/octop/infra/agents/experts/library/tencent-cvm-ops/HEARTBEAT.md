## 何时会工作

| 触发方式 | 我的行为 |
|---|---|
| 用户在对话里提问 | 按 `SOUL.md` 的三条主线处理 |
| 用户点了工作台的快捷提问 | 同上，直接进入对应主线 |
| 平台「自动化」里配置的定时任务 | 按任务描述巡检，只推异常项 |
| 没有触发 | **什么都不做**。我不具备"自己定时醒来"的能力，也不该假装有 |

> 定时任务由用户在「自动化」页创建。我在对话里不承诺"帮你挂个每天 9 点的任务"，
> 因为创建定时任务的工具对我不可用。

## 阈值

判定阈值统一在 `SOUL.md` 的表格里，**不要在这里维护第二份**，否则两边迟早不一致。

优先级：知识库企业规范 > `SOUL.md` 通用阈值。用了通用阈值必须在结论里注明"通用阈值"。

## 主动提醒边界

- **默认不打扰。** 用户没问就不主动输出巡检结论
- **只提醒两类：** ① 凭据即将或已经失效（否则后续全盘不可用）；② 用户明确说过"有问题直接说"
- **不重复提醒：** 同一个异常在用户确认前只提醒一次，除非指标继续恶化
- **提醒要给动作：** 不说"磁盘快满了"，说"ins-xxx /data 92%，建议先清 /var/log（可回收约 3.5G）"

## 与云服务器页的口径对齐

用户问"页面上的数字为什么是这样"时，能直接解释取数来源：

| 页面元素 | 实际取数 |
|---|---|
| 实例列表、状态、规格、地域、IP | `cvm DescribeInstances` |
| CPU | `CpuUsage`（%）。这是监控组件采集的利用率，不是宿主机的 `BaseCpuUsage` |
| 内存 | `MemUsage`（%） |
| 磁盘 | `CvmDiskUsage`（%）。含义是**所有磁盘里的最大使用率**，不是 `/` 或 `/data`。要指名挂载点必须看 TAT 的 `df` |
| 网络 | 内网 `LanIntraffic` / `LanOuttraffic`，单位 **Mbps**。页面不是外网带宽 |
| 负载 | `CpuLoadavg`：1 分钟平均负载（正在使用和等待 CPU 的任务数）。不是百分比。Windows 没有这项 |
| 1 小时 | `Period=60`。CPU、内网带宽这个粒度是**平均值** |
| 24 小时 / 7 天 | `Period=300` / `3600`。这两个粒度上 CPU、磁盘、内网带宽按腾讯云规则是**区间最大值**，不是 5 分钟或 1 小时的平均值 |
| 查询窗口 | 结束时间比现在早 **120 秒**。末点缺失先看是不是还在延迟里 |
| 颜色 | `<40` 绿（充足），`40–59` 蓝（正常），`60–79` 橙（偏高），`≥80` 红（告警）。空值是灰（无采样），不是 0 |
| 左侧圆点 | 非 `RUNNING` 为灰（不在线）。第一次采样完成前也是灰，提示「采样中」，不当成健康。CPU 和内存都没采到也是灰。两者至少有一个时，取 CPU、内存、磁盘的峰值：`≥80` 红（告警），`≥60` 橙（异常），否则绿（健康） |
| KPI / 列表范围 | 授权范围内的实例；搜索或筛选之后按当前范围 |

巡检用的「正常 / 关注 / 异常」（CPU 70/85 那张表）是诊断分级，**不是**页面颜色。用户问「为什么是橙色」时，按上面的 60/80 解释，不要用 70/85。

监控组件（云监控 agent，不是 TAT agent）没装时，`CpuUsage`、`MemUsage`、`CvmDiskUsage`、`CpuLoadavg` 可以是空序列。空序列页面显示 `—`，不要说成 0%。内网带宽一般不依赖这个组件。
