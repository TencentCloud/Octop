# 云服务器诊断报告

单机诊断、健康巡检、用户要求出报告时，只用这一份。不要再用带表情符号的旧模板，也不要另起 100 分制去解释页面颜色。

## 两套口径，必须分列

| 列 | 用途 | 规则 |
|---|---|---|
| 页面色带 | 解释工作台上的颜色 | `<40` 充足，`40–59` 正常，`60–79` 偏高，`≥80` 告警。空值是无采样，不是 0 |
| 诊断分级 | 这份报告的结论 | 正常 / 关注 / 异常。阈值以 `SOUL.md` 的巡检表为准；知识库有企业阈值时改用企业阈值并注明 |

`≥80` 在页面上是告警，不是「健康」。

## 指标怎么写

| 指标 | 写法 |
|---|---|
| CPU | `CpuUsage`，单位 %。1 小时视图的点是 60 秒平均值；24 小时、7 天的点是区间最大值 |
| 内存 | `MemUsage`，单位 % |
| 磁盘 | `CvmDiskUsage` 是所有磁盘中的最大值，不能写成 `/` 或 `/data`。有 `df` 再另起一行写挂载点 |
| 网络 | 内网入 `LanIntraffic`、内网出 `LanOuttraffic`，单位 Mbps。不要写成外网带宽 |
| 负载 | `CpuLoadavg` 是 1 分钟平均负载，写成 `1.8 / 2 核`。不是百分比。Windows 没有这项 |

云监控组件没装时，CPU、内存、磁盘、负载写「未采集」。TAT 的 `tat_agent` 离线时，OS 层写「未采集」，不要用云监控数字冒充 `df` 的结果。监控窗口的结束时间比现在早 120 秒。

没有采到的数字留空，禁止编造。正常项在聊天正文里不展开。

## 聊天正文

```
# 云服务器诊断报告

| 项 | 内容 |
|---|---|
| 对象 | 名称 · 实例 ID · 地域 · 规格 |
| 时间 | 监控窗口 · 是否含 TAT |
| 结论 | 正常 / 关注 / 异常 · 一句话 |

## 指标

| 指标 | 最新值 | 页面色带 | 诊断分级 | 口径 |
|---|---|---|---|---|
| CPU | | | | |
| 内存 | | | | |
| 磁盘 | | | | 所有磁盘最大值 |
| 内网入 / 出 | | — | | Mbps |
| 负载 | | — | | 1 分钟平均负载 / 核数 |

## 异常与关注

- 时间 · 数值 · 来源（GetMonitorData 或 TAT 命令）

## 建议

1. 动作
2. 影响与回滚
3. 验证

## 附注

未采集项和原因。没有则省略本节。
```

多台巡检时，「指标」改成一台一行的汇总表，列：实例、地域、状态、CPU、内存、磁盘、负载、诊断分级。只在「异常与关注」里展开有问题的实例。

## 归档文件

需要留下文件时，按同目录的 `diagnosis-report.html` 填入上面的内容，去掉未使用的行和占位符，写到：

`output/cvm-diagnosis-<实例或范围>-<YYYYMMDD-HHmm>.html`

然后用 `send_file_to_user` 发出。不要在回复里粘贴工具返回的 URL。
