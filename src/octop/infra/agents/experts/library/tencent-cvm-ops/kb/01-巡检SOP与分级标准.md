# CVM 巡检 SOP 与分级标准

适用范围：授权范围内的腾讯云 CVM。轻量应用服务器不在云服务器页里，要单独用 `lighthouse` API。适用于日常巡检、批量巡检、变更前后确认。

## 一、巡检范围约定

1. 默认范围 = 用户当前选中的实例；用户明确说"全部/所有/整个账号"才做全量。
2. 全量超过 200 台时必须先说明"将并发采集，预计耗时 N 分钟"，并给出抽样建议。
3. 跨地域巡检必须按 region 分批调用 TAT（TAT 是 region-scoped，不支持跨区一次调用）。
4. 轻量应用服务器可以用 TAT，但一次 `RunCommand` 不能和 CVM 放在同一个 `InstanceIds` 里。实例必须是 `RUNNING`、VPC，且 `tat_agent` 在线。基础网络实例不能用 TAT。

## 二、采集项（固定清单）

| 层 | 数据 | 来源 | 是否必需 |
|---|---|---|---|
| L1 云端 | 实例状态、规格、地域、公网 IP。包年包月才有 `ExpiredTime`，按量计费没有到期时间 | DescribeInstances | 必需 |
| L1 云端 | CPU、内存、磁盘、内外网带宽、负载 | GetMonitorData（QCE/CVM） | 必需 |
| L2 OS | uptime、load、核数、时间同步状态 | TAT + cvm-patrol.sh | 有 TAT 时必需 |
| L2 OS | free、swap、OOM 记录、top 内存进程 | 同上 | 有 TAT 时必需 |
| L2 OS | df -h、df -i、根目录 top 目录、deleted-but-open | 同上 | 有 TAT 时必需 |
| L2 OS | ss -s、established top、监听端口、网卡 errors | 同上 | 有 TAT 时必需 |
| L2 OS | systemd failed units、僵尸进程、内核错误 | 同上 | 有 TAT 时必需 |

采集原则：**一台机器只下发一次脚本**，不要在 TAT 上反复跑 `df`/`free`/`uptime` 单条命令。

## 三、分级阈值（通用基线）

未命中企业规范时使用本表，并在结论中注明"通用阈值"。

| 指标 | 正常 | 关注 | 异常 |
|---|---|---|---|
| CPU 使用率 | < 70% | 70%–85% 且持续 ≥10 分钟 | > 85% 或满载 |
| 内存使用率 | < 75% | 75%–90% | > 90%，或 swap 使用 > 20% |
| 磁盘使用率（根盘） | < 75% | 75%–85% | > 85% |
| 磁盘 24h 增长率 | < 2% | 2%–5% | > 5%（按线性外推不足 3 天写满） |
| inode 使用率 | < 60% | 60%–80% | > 80% |
| 单核负载 load/ncpu | < 1.0 | 1.0–1.5 | > 1.5 持续 10 分钟 |
| IO wait | < 5% | 5%–20% | > 20% |
| 网卡 errors/drops | 0 | 偶发 | 持续增长 |
| systemd failed | 无 | 非关键服务 | 关键服务 failed |
| 时间同步 | 已同步 | 漂移 < 60s | 漂移 > 60s |

判定优先级：先看**变化**再看绝对值。`磁盘 78% 但 24 小时涨了 8%` 比 `磁盘 92% 且一周稳定` 更紧急。

## 四、诊断报告

输出格式以技能目录 `tencentcloud-infra/references/diagnosis-report.md` 为准。

- 聊天用该文件里的 Markdown。归档时填写同目录的 `diagnosis-report.html`。
- 页面色带（`<40` 充足，`40–59` 正常，`60–79` 偏高，`≥80` 告警）和本节的诊断分级是两列。页面上 `≥80` 是告警。
- `CvmDiskUsage` 是所有磁盘的最大值。没有 TAT 的 `df` 时，不要写成某个挂载点。
- 未采集写「未采集」。正常项不在正文展开。

## 五、降级规则

| 情况 | 降级方式 | 报告标注 |
|---|---|---|
| TAT agent 离线 | 跳过 L2，只用云监控 | "仅云端指标，置信度较低" |
| 缺 du/lsof/ss | 用替代命令，或跳过该项 | "XX 项未采集" |
| 轻量应用服务器 | 用 `lighthouse` API 与 `QCE/LIGHTHOUSE`，TAT 单独下发，不和 CVM 混批 | "轻量实例，未与 CVM 混用 TAT" |
| 权限不足 | 明确缺哪个 CAM 权限 | "缺权限，未执行" |

## 六、巡检节奏建议

- 每次变更前后：对受影响实例做一次快速巡检（quick_scan + 关键指标）
- 每日：全量或标签范围巡检一次，只推异常
- 每周：输出容量趋势（磁盘/内存增长速率），给出扩容窗口建议
