# 变更门控与回滚规范

适用于所有对生产实例产生副作用的操作。原则：**能只读就不动手，非要动手就要能回滚。**

## 一、四级门控

| 等级 | 判定 | 典型操作 | 要求 |
|---|---|---|---|
| 🟢 低 | 不改变任何状态 | 查询、Describe*、GetMonitorData、读日志、巡检、出报告 | 直接执行 |
| 🟡 中 | 局部可逆，可能短暂影响单服务 | 清理日志/旧归档、`journalctl --vacuum-time`、`logrotate -f`、`systemctl reload/restart 单服务`、重开日志句柄、调 nf_conntrack_max | 说明「动作 + 影响面 + 回滚方式」，等用户回复 yes |
| 🔴 高 | 影响整机或网络可达性 | 重启/停机/启动实例、改安全组、改内核参数、扩缩容、解绑/挂载云盘、重置密码 | 必须等用户**明确说出实例 ID**，并给出容量与回滚评估 |
| 💀 禁止 | 不可逆或大范围 | 批量重启 ≥50% 节点、`rm -rf` 无备份、`DROP TABLE`、`mkfs`、改 `/etc/fstab`、删系统目录 | 直接拒绝，给安全替代方案 |

## 二、🟡 / 🔴 的标准话术结构

```
动作     重启 ins-xxxx 上的 nginx（systemctl restart nginx）
影响     该节点 5–15 秒不可用；当前 4 台中 3 台在线，重启期间剩余 3 台承接流量
回滚     若启动失败：systemctl status 查错 → 回滚到 /etc/nginx/nginx.conf.bak.<ts> 再 reload
验证     curl -I 127.0.0.1:80 返回 200；ss -tlnp 显示 80 监听；nginx error_log 无新增 error
请确认   回复 "确认重启 ins-xxxx"
```

缺任何一项都不要发起执行。

## 三、批量与集群变更

1. **串行**：一次一台，验证通过再下一台；禁止"批量重启一把梭"
2. **保容量**：执行前算出「当前可用 / 变更后剩余」，剩余 < 50% 直接拒绝并说明
3. **滚动窗口**：优先低峰期；有 CLB 时先摘除节点再操作，操作完再挂回
4. **限速**：批量操作之间至少间隔 30 秒，避免雪崩

## 四、回滚规范

| 变更类型 | 备份要求 | 回滚方式 |
|---|---|---|
| 改配置文件 | 先 `cp file file.bak.$(date +%s)` | 覆盖回 bak 后 reload |
| 改 systemd unit | 同上 + `systemctl daemon-reload` | 覆盖后 daemon-reload + restart |
| 删文件/清日志 | 确认可重建（日志/缓存），业务数据不删 | 无法回滚 → 必须先确认 |
| 改安全组 | 记录原规则 | 按原规则恢复 |
| 改内核参数 | 记录原值 | `sysctl -w k=v` 恢复 |

## 五、执行后必须复查

1. 重新采集同一组指标（`quick_scan.sh` 或 `cvm-patrol.sh`）
2. 比对前后数值，确认目标达成（空间释放 / 进程恢复 / 负载回落 / 端口监听）
3. 观察 3–5 分钟，确认无二次异常（NRestarts 不再增长、OOM 未复发）
4. 报告写清：改了什么 / 依据 / 当前状态 / 遗留风险

## 六、失败处理

- 执行失败**先回滚再解释**，不要边试边改
- 回滚失败立即停止后续操作，如实说明卡在哪一步
- 连续两次失败 → 停止并建议人工介入，不要循环重试

## 七、禁止操作清单（硬约束）

| 禁止 | 原因 | 替代方案 |
|---|---|---|
| 批量重启 ≥50% 节点 | 服务整体不可用 | 滚动重启，保留 ≥50% 容量 |
| `rm -rf` 未确认路径 | 不可逆 | 先 `ls`/`du` 确认，移动到 /tmp 观察后再删 |
| `DROP TABLE` / `TRUNCATE` | 数据不可恢复 | 备份 + 人工确认 |
| 改 `/etc/fstab` | 重启后系统可能起不来 | 用 UUID 挂载，改完 `mount -a` 验证 |
| 关闭防火墙/SELinux 图省事 | 安全风险 | 精确放行端口/加策略 |
