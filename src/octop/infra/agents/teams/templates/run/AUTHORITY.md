# 权威声明（AUTHORITY）

> **本表是「单源化」的唯一约定**：每个事实**只有一份权威**、**只有一个写者**，其他文件**只许引用**。
> 起草：`architect`（design 阶段）｜校验：spec-review 门禁。
>
> 为什么需要它：返工里命中「同一事实多份拷贝 / 多写者 / 口径漂移」的比例最高。本表的目的是把这件事
> **提到事前**：先声明，再写。

## 怎么写

- **一行一个事实**。事实 = 会被多份文件提到、且**必须一致**的东西：术语与中英口径、拒绝码词表、
  功能开关的数量与 key、章节编号、指标口径与数值、边界清单、优先级定义……
- **第 1 列 = 原子事实名**（单个词 / 短语，**不得**用 `、` / `，` 作并列枚举），且必须能在权威文件里
  以定义式逐字出现（标题 / `**名**：` / 两列表格 / `「名」：` / `- 名：`）。
- **唯一写者**：那个人负责改它；**其他人改 = 违规**。
- **权威文件**必须是本 run 目录里真实存在的文件。
- 定不下来的事实**不要写进来**（写了就要守）。

## 校验规则（spec-review 会逐条查）

1. **格式**：每行必须 4 列且都非空（空行 / 表头 / 分隔行不算）。
2. **文件真实**：`唯一权威文件` 必须在本 run 目录里存在。
3. **写者合法且唯一**：写者必须是编制里的角色；**同一个权威文件不得有两个写者**。
4. **无自相矛盾**：同一个「事实类别」不得指向两个不同的权威文件。
5. **纳入治理**：本 run 里的核心工件至少要出现在某一行里，否则它没被纳入单源化治理。
