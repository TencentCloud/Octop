# 测试用例自动生成器（Test Case Generator）

## 概述

本 skill 帮助测试工程师和开发人员根据需求文档或功能模块描述快速生成规范的功能测试用例，覆盖正常流程、边界条件和异常场景。

典型使用场景：
- 开发完成新功能后，生成功能测试用例
- 版本发布前，生成回归测试用例
- 需求变更时，补充或更新测试用例
- 编写测试计划前的用例设计

## 工作流程

### 第一步：收集测试信息

通过对话收集以下关键信息：

**必填信息**：
1. **测试对象**：
   - 功能模块名称：___
   - 所属系统：输液监控系统 / 物联网引擎 / 管理平台 / 其他
2. **输入材料**：
   - 需求文档（粘贴内容或上传文件）
   - 或详细的功能描述
3. **测试类型**：
   - 功能测试
   - 回归测试（针对已有功能的变更验证）
   - 冒烟测试（核心功能快速验证）

**选填信息**：
1. **测试环境**：测试环境 / 预发布环境 / 生产环境
2. **特殊要求**：如需要覆盖的浏览器、必须验证的兼容设备等
3. **用例优先级**：P0/P1/P2 三级分布

### 第二步：分析功能模块

根据输入材料，分析功能模块的以下方面：

**功能分解**：
```
功能模块
├── 子功能1
│   ├── 操作1.1
│   └── 操作1.2
├── 子功能2
│   ├── 操作2.1
│   └── 操作2.2
└── 公共流程
    ├── 登录认证
    └── 权限校验
```

**识别关键业务流程**：
1. 主要操作路径（Happy Path）
2. 分支条件路径
3. 异常处理路径

### 第三步：生成测试用例

对每个功能点，生成以下类型的测试用例：

| 用例类型 | 说明 | 数量占比建议 |
|----------|------|--------------|
| 正常流程 | 验证功能的正确实现 | 40-50% |
| 边界测试 | 验证边界条件处理 | 20-30% |
| 异常测试 | 验证异常输入和错误处理 | 20-30% |
| 权限测试 | 验证不同角色的访问控制 | 10-20% |

**测试用例模板**：

```
用例编号: TC_{模块}_{序号}
用例标题: {简述测试目的}
优先级: P0/P1/P2
前置条件: {测试前的系统状态}
测试步骤:
  1. {操作步骤1}
  2. {操作步骤2}
  3. {操作步骤3}
预期结果: {期望的系统响应}
测试数据: {使用的测试数据}
```

## 输出约定

- 测试用例默认保存为 Excel 格式：`/sandbox/workspace/output/测试用例_{模块名称}_{日期}.xlsx`
- 测试计划摘要保存为 Markdown：`/sandbox/workspace/output/测试计划_{项目名称}_{日期}.md`
- Excel 表格格式：
  - Sheet1：用例列表
  - Sheet2：用例详情
  - Sheet3：测试计划摘要

## 脚本说明

### generate_test_cases.py

生成测试用例的 Python 脚本：

```bash
python3 scripts/generate_test_cases.py \
    --module "输液监控器管理" \
    --output "/sandbox/workspace/output/test_cases.xlsx" \
    --priority P0,P1,P2
```

参数说明：
- `--module`：功能模块名称
- `--output`：输出文件路径
- `--priority`：生成用例的优先级分布

## 注意事项

- 生成的测试用例为模板，实际使用前需根据项目实际情况调整
- 边界测试的边界值需要根据实际业务规则确定
- 测试数据中的敏感信息（如真实患者信息）需脱敏处理
- 建议在正式测试前进行用例评审
- P0用例应覆盖所有核心业务路径
