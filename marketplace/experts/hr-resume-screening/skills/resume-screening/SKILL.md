# 简历分析器（通用版 · resume-screening）

## 这个 skill 解决什么

把「简历 → 面试 → 转正」串成一条有标准、可复用、可归档的流水线：

1. **招聘前**先存档岗位诉求（Job Card），定死硬门槛和否决项
2. **招聘中**每份简历对着 Job Card 分析，出「面否/可面」判断 + 面试问题清单
3. **转正时**把简历分析的信号层结论迁移成员工画像基线，衔接 AGM 能力体系

> 核心原则：**简历分析不是「看人」，是「列证据缺口」**。结论可能是信息不足，不是能力不够。

## 能力边界（不做什么）

- 只做「候选人简历」分析，**不做已入职员工的能力评估**（那是 `agm-employee-analysis` 的职责）
- 只做单份简历/候选人对比，**不做群体批量筛选**（大量简历自动排序/打分需另配流程）
- 只给「面否/可面」建议和验证方式，**不替使用者做最终人事决策**
- 简历阶段只判「信号层」（置信度 ≤55%），**不判「能力层」**——能力层级要等 AGM 答题数据裁决

## 已知限制与常见误用

- **扫描版 PDF（无文字层）**：`resume_to_text.py` 默认走文本层提取，扫描版会提示「未提取到文本层」，需加 `--ocr`（依赖 markitdown）或让对方发文字版/截图
- **水印过滤不是 100% 无损**：斜向水印的孤立字符依赖字符集识别，极端情况可能残留少量碎片或误删孤立数字，转换产物需人工快速扫一眼确认核心信息（姓名/学校/经历）完整
- **简历 ≠ 能力**：简历只提供「信号层」证据，别把简历写得好直接等同于能力高（置信度封顶 55%）
- **Job Card 是尺子，不是枷锁**：否决项命中即 pass，但如果岗位诉求变了，先更新 Job Card 再分析，别拿过时的尺子量新人

## 完整工作流（三阶段）

| 阶段 | 触发 | 做什么 |
|------|------|--------|
| **A. 初始化** | 首次使用 / 新岗位 | 引导使用者填 Job Card（岗位诉求 + 硬门槛 + 否决项），确认后存档 |
| **B. 分析** | 丢来简历 | 四步两线：简历→文本 → 事实底稿 → 时间线/信号/层级 → 匹配 + 面试题 + 录用建议 |
| **C. 转正闭环** | 说「转正 / 建画像」 | 迁移信号层结论为画像基线，确认后落盘 |

## A. 初始化：Job Card 前置（安装即确认）

> **没有 Job Card 前，不分析简历。** 首次使用时，AI 先引导使用者确认岗位诉求，确认后再执行分析。这是「装完 skill 先确认信息再干活」的关键。

### 触发条件

- 首次使用（skill 目录下 `job-cards/` 为空或没有对应当前岗位的 Job Card）
- 使用者换了新岗位要招人

### 流程

1. AI 检测到无对应岗位 Job Card → 停下来问：「这个岗位是什么？主要做什么？」
2. 按 `references/job-card-template.md` 引导使用者填：岗位职责 / 硬门槛 / **否决项** / 软要求 / 岗位认知层级
3. **重点确认否决项**：明确问「有没有什么情况是一票否决、绝对不要的？」——这是使用者自己定，skill 不预设
4. 确认后存档到 `job-cards/{岗位名}-job-card-{YYYYMMDD}.md`
5. 之后分析简历时，自动读取对应岗位的 Job Card 作为匹配基准

> ⛔ 否决项一旦确认就固定，分析时命中即触发，不临时放宽口径。

## B. 分析阶段（四步两线）

> 使用者主导流程，AI 每步只推进一次。使用者每次只丢一步的东西过来，AI 给对应产出，不越级。

| 阶段 | 使用者做什么 | AI 产出 |
|------|-----------|---------|
| ① 简历 → 线上题 | 发简历（PDF/文字）| 出**线上面试问题清单**（分型：应届/已工作，专业题 + 简历核验命中项）|
| ② 线上 → 分析 | 把对方的**回答原话**给我 | 判定 → **约线下 / 不约 / 可约但重点验什么** |
| ③ 线下题 | 决定约了之后找我要 | 出**线下面试深挖问题**（针对 ② 暴露的风险项 + 岗位核心能力）|
| ④ 线下 → 终评 | 真线下后把回答原话给我 | 结合线上+线下 → **最终录用建议**（可录/不录/有条件录 + 条件）|

**关键规则**：
1. 逐步推进，①完才能②，③完才能④
2. ②④ 判定要「回答原话」，不接受「他说得还行」这种总结，追问要原话
3. ② 不约 = 流程终止，不自动进③
4. ④ 只给建议不替使用者决定

### Step 0：简历文件 → 文本

内嵌脚本 `scripts/resume_to_text.py`，无需额外安装转换工具：

```bash
# PDF（有文本层，含平台水印过滤）
python scripts/resume_to_text.py "简历.pdf" -o /tmp/resume.md

# 扫描版 PDF / 图片（OCR，需 pip install 'markitdown[all]'）
python scripts/resume_to_text.py "简历.jpg" --ocr -o /tmp/resume.md
```

- 脚本自动过滤招聘平台（BOSS 直聘等）斜向水印，避免水印字符混入正文
- 转换完确认拿到干净文本，再进入 Step 1

### Step 1：事实底稿提取

| 维度 | 内容 |
|------|------|
| 基础 | 性别/年龄/籍贯/毕业届数 |
| 教育 | 学校/专业/学历/起止时间 |
| 主修/证书 | 证书、技能 |
| 实习/工作经历 | 每段：公司/岗位/起止/职责/成果 |
| 校内/项目 | 校园经历、项目 |
| 求职意向 | 简历上的意向岗位 |
| 薪资期望 | 若有 |

### Step 2：时间线完整性检查（必做，第一步不是亮点是对平时间）

1. **入学年龄推算**：本科入学年 ≈ 出生年 + 18/19。晚 2-3 年 → 中间有 Gap，最常见是专升本/成人本科
2. **学历时长检查**：本科正常 4 年；显示 2 年 → 必是专升本/插本/成人本科，简历省略了专科段
3. **在职学历信号**：非全日制本科常写「成人/函授」，或起止 2.5-3 年且与工作期重叠
4. **空窗期检查**：毕业到当前、或两段经历之间 ≥3 个月空窗 → 记录，面试验证

> ⛔ 时间线命中项（教育年限异常、空窗、在职学历）**是否触发否决**，取决于使用者 Job Card 里的否决项定义。skill 不预设「专升本一律 pass」这类口径——那是使用者的决定。

### Step 3：信号风险识别

| 风险类型 | 识别信号 | 处理 |
|------|------|------|
| 信息省略 | 学历只写最高段、经历时间拼接有 Gap | 面试问 + 学历核验 |
| 数字夸大 | "效率提升 30%" 无基准无方法 | 面试要具体场景、方法、度量 |
| 事迹存疑 | 与常识/公开事实冲突 | 标注存疑，追问细节，其他描述打折听 |
| 意向错位 | 简历意向 ≠ 投递岗位 | 入职动机待验，1-2 月复验稳定性 |
| 经历注水 | 短经历但头衔大 | 面试验证实际职责边界 |
| AI 生成痕迹 | 结构完美对称/全编号/零口语/产出时点不合理 | 按「AI 生成物证据排除」处理 |

### Step 4：AGM 信号层预判

> 判定逻辑：`references/agf-analysis-logic.md`（12 格层级 / 8 维 / 行为证据 / 快速判定表 / 防误判过滤器）。

- 简历写出的 → 显性信号（L1.5-L2.2 可给，高如 L2.2 需面试确认）
- 简历没写但结构暗示的 → 待验证信号
- 无证据的维度 → 「无法判定」，不猜
- **置信度封顶 55%**（面试前）/ 70%（面试后）

### Step 5：岗位匹配（对着 Job Card）

| 维度 | 评估 |
|------|------|
| 岗位认知需求 | Lx（来自 Job Card ⑥）|
| 候选人信号 | Lx（Step 4 预判）|
| 硬门槛核对 | 逐项对 Job Card ③，列「满足/不满足」|
| 方向匹配 | 匹配/存疑/不匹配 + 具体证据 |
| 培养方向 | 定制培养路径建议 |

### Step 6：否决项判定（自定义，命中即 pass）

- 逐项对照 Job Card ④ 的否决项，检查 Step 2/3/5 的发现是否命中
- **命中任一否决项 → 直接「面否」**，不再进入面试问题清单（或清单标注已失效）
- 未命中 → 继续 Step 7
- 判断不了 → 标「待确认」，问使用者，不自行下结论

### Step 7：面试问题清单（核心交付物，拆线上/线下）

**先分型再出题**（应届生 vs 已工作）：

| 分型 | 判断依据 | 出题策略 |
|------|---------|---------|
| 应届生（毕业 ≤1 年）| 无全职经历或只有实习 | 考思维/态度（情景假设、第一反应），看「值不值得培养」|
| 已工作（毕业 ≥1 年）| 有 1 段以上全职经历 | 考经历真实性（"你以前怎么处理"），看「是不是真做过」|

**专业性问题的来源**：从 Job Card ② 的岗位职责出题，不考知识（新人不会），考「岗位核心场景的第一反应对不对」。按候选人专业/实习背景定制——用他简历里已有的经历出思维题，别拿岗位场景套所有人。

**线上面试（初筛）**：专业题为主（≥3 个），简历核验为辅。**线下面试（深挖）**：STAR 行为面试 + 情景假设 + AGM 层级信号。

每条问题给：问题原文 + 验证什么 + 怎么判好坏（✅ 好 / ❌ 坏）。

### Step 8：录用建议 + 风险控制

- **面否/可面/倾向录用** 三档 + 理由（命中否决项 → 直接面否）
- 风险控制清单：入职前学历核验、简历经历逐段复核、试用期观察点
- 不替使用者做人事决策——给证据、给选项、给验证方式

### Step 9：归档

- 收简历即建档：生成 `resumes/{姓名}-简历分析-{年份}.md`，②③④ 每阶段即时回填
- 简历原件一并归档
- 多候选人对比表：只在使用者明确要求时做，不主动做

## C. 转正闭环：简历 → 画像

> 详见 `references/profile-baseline-template.md`。**手动触发 + 确认**，不自动写。

### 触发

员工转正，使用者说「转正」「建画像」「转员工画像」。

### 流程

1. AI 展示要写入画像的基线信息（信号层结论 / 风险项 / 待验证维度），等使用者确认
2. 确认后：
   - **已安装 `agm-employee-analysis`** → 按其完整画像模板建画像
   - **未安装** → 先按 `references/profile-baseline-template.md` 建「基线画像」，标注待验证
3. 简历分析档案保留不删（候选历史），画像与档案并存

### 关键规则

- 迁移的是**结论**（层级预判/风险项/验证点），不是复制整份简历
- 简历信号层置信度 ≤55%，正式 AGM 答题数据出来后裁决修正（简历可能高估）
- 未答题可先建「基线画像」，不阻塞

---

## 关键规则

1. **Job Card 前置**：没有岗位诉求（Job Card）不分析简历，先确认再动手
2. **否决项自定义**：skill 不预设任何一票否决项，全部由使用者定义，命中即触发不临时改口径
3. **时间线检查是第一步**：先对平时间再谈亮点——教育年限、入学年龄、空窗期三根标尺
4. **信息省略 ≠ 造假**：双面解读，但省略的教育经历必须进面试问题 + 核验清单
5. **简历只能判「信号层」**：置信度封顶 55%（面试前）/ 70%（面试后）
6. **面试问题必须「可判好坏」**：每条带好/坏标准，不然问了也白问
7. **必须给录用建议 + 风险控制**：只说「有风险」不给「怎么验」= 不合格
8. **不替使用者做人事决策**：给证据、选项、验证方式，不直接说「招」或「不招」
9. **转正画像手动触发 + 确认**：展示基线 → 等确认 → 落盘

## Skill Improvement

每次使用后反思：是否有新的简历风险模式没被覆盖（如新的学历/经历造假手法）→ 更新本 skill 的 Step 2/3。
