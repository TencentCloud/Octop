# Job Card 模板

> 招聘前先填这张卡，把岗位诉求存档。之后每份简历都对着这张卡分析，
> 避免「边看边想、口径漂移」。Job Card 是简历分析的「尺子」，不是「备忘录」。

## 为什么要有 Job Card

1. **否决项固定**：学历门槛、一票否决项在招聘前定死，分析时命中即触发，不临时改口径
2. **岗位职责对齐**：分析"这个人合不合适"之前，先明确"这个岗位到底要人干什么"
3. **可复用**：同一岗位招多人时，一张卡对多份简历，标准一致

## 使用时机

首次使用 `resume-screening` 时，AI 会先引导你填这张卡并存档（`job-cards/` 目录）。
之后分析简历时，AI 自动读取对应岗位的 Job Card 作为匹配基准。
没有 Job Card 时，AI 会先问你要岗位诉求，确认后再分析——不会「凭空分析」。

## Job Card 结构

### ① 岗位基本信息

| 字段 | 内容 |
|------|------|
| 岗位名称 | （如「初级运维专员」「客户服务专员」）|
| 所属团队 | |
| 汇报对象 | |
| 招聘人数 | |
| 期望到岗 | |

### ② 岗位职责（Job Card 核心）

- 这个岗位日常做哪几类事？（列 3-5 条）
- **最核心的一件事是什么？**（岗位存在的根本原因）
- 这个岗位最容易在什么事上出问题？

> 示例（运维专员）：
> - 日常：处理客户订单异常、退件跟进、物流查询、账单核对
> - 最核心：客户问题从「反馈」到「解决」的闭环，不出二次投诉
> - 最容易出问题：先承诺后查证（跳过查证直接答应客户）

### ③ 硬门槛（不满足即筛掉，但通常可沟通）

| 维度 | 要求 |
|------|------|
| 学历 | （如「本科及以上」）|
| 经验年限 | |
| 证书/技能 | （如「英语六级」「会 Python」）|
| 其他硬性 | |

### ④ 否决项（一票否决，命中即 pass）

> 这是**完全自定义**的部分。使用者自己定「什么情况绝对不要」。
> 下面是示例，仅供参考——使用者按自己公司实际情况填写，**skill 不预设任何否决项**。

| # | 否决项 | 触发信号（简历/面试里怎么识别）|
|---|--------|-------------------------------|
| 示例1 | 学历造假 / 学信网核验不符 | 学历信息与学信网对不上 |
| 示例2 | 经历时间线严重对不上（隐瞒空窗/学历段）| 教育-经历时间拼不齐，追问后仍回避 |
| 示例3 | 离职原因全是甩锅公司/同事 | 每段离职都归因外部，无自我反思 |
| （自定义）| ... | ... |

> ⛔ 否决项一旦确认，分析时命中即触发「面否」，不临时放宽口径。

### ⑤ 软要求（加分项，不是否决项）

- 能力维度（AGM 层级期望，如「至少 L1.3 精进执行」）
- 性格/价值观匹配（如「能接受重复性工作并主动找优化点」）
- 成长潜力（如「有从执行到优化的发展空间」）

### ⑥ 岗位认知需求层级（AGM）

- 这个岗位需要候选人具备什么认知层级（L1 / L2 / L3…）？
- 为什么是这个层级？（基于岗位复杂度，不是拍脑袋）

> 参考：`references/agf-analysis-logic.md` 的「层级速记」——
> L1 执行 / L2 优化流程 / L3 建系统 / L4 设计组织。
> 客服/运维专员通常 L1.3-L2.2；能独立搭流程的资深岗 L2.3-L3.1。

## 存档格式

Job Card 存到 `job-cards/{岗位名}-job-card-{YYYYMMDD}.md`。
同一岗位更新时，旧版保留（命名带日期），分析时用最新版。
