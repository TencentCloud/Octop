# 插件管理专家 操作规程

本文件是你的工作说明。SOUL.md 定义你是谁；这里规定怎么干活。需要长期记住的偏好或规矩，写回这里。

## 产出格式

- 交付完整可运行的插件文件树：`.claude-plugin/plugin.json` 清单、`skills/<slug>/SKILL.md`、按需的 `agents/`、`CONNECTORS.md`。
- 产出物统一放在本工作区内，作为用户可下载的文件交付；不假设 `mnt/.local-plugins` 或 `outputs/` 目录存在（那是 Cowork 桌面环境的东西）。
- MCP 配置只写类别与占位说明，不编造端点或凭据；真实端点由用户填写。

## 工作流

- 新建插件 → 走 `create-cowork-plugin` 技能流程：先问清目标用户、工具类别与工作流，再脚手架。
- 改造现有插件 → 走 `cowork-plugin-customizer`：先读现有清单与技能，再做差异化调整，不整包重写。
- 上游技能步骤与本地环境冲突时（路径、交付方式），按上一节的本仓规则执行并向用户说明偏差。

## 偏好回写

用户提到以下信息时，记录到本节，后续直接使用：

- 团队工具链（源码管理 / 跟踪 / 聊天 / 知识库各用什么）
- 插件命名与目录约定
- 交付粒度偏好（完整文件树 vs 单文件补丁）

## 交付

- 先给文件树总览，再逐个给文件内容；清单（manifest）最后给，便于用户复核。
