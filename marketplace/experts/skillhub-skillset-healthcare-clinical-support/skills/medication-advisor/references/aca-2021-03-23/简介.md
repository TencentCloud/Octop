## 概述

腾讯 AI 临床助手（ACA）合理用药 API 基于腾讯云 API 3.0 框架，提供药品标准化、诊断标准化、频次/途径标准化及综合处方审核能力。

## 接入域名

| 环境 | 域名 |
|------|------|
| 生产环境 | `aca.tencentcloudapi.com` |
| 开发联调环境 | `aca.dev.tencentcloudapi.com` |

也支持指定地域域名，例如广州地域：`aca.ap-guangzhou.tencentcloudapi.com`。

## 鉴权方式

使用腾讯云 API 3.0 TC3-HMAC-SHA256 签名鉴权。调用时需在 HTTP Header 中携带以下参数：

| Header 参数 | 说明 |
|-------------|------|
| `Authorization` | TC3-HMAC-SHA256 签名串 |
| `Content-Type` | `application/json; charset=utf-8` |
| `Host` | 接口域名 |
| `X-TC-Action` | 接口名称，如 `MatchDrug` |
| `X-TC-Version` | 接口版本，固定为 `2021-03-23` |
| `X-TC-Timestamp` | Unix 时间戳（秒） |
| `X-TC-Region` | 地域，如 `ap-guangzhou` |
| `X-TC-Token` | 临时证书 Token（使用临时密钥时必填） |

密钥（SecretId / SecretKey）通过腾讯云控制台获取。禁止将密钥硬编码在代码或配置文件中提交到版本库。

推荐通过环境变量或独立配置文件提供密钥：

```bash
export TENCENTCLOUD_SECRET_ID=your-secret-id
export TENCENTCLOUD_SECRET_KEY=your-secret-key
```

或使用配置文件（推荐路径 `~/.config/medication-advisor/aca.json`）：

```json
{
  "secret_id": "your-secret-id",
  "secret_key": "your-secret-key",
  "region": "ap-guangzhou",
  "endpoint": "aca.tencentcloudapi.com"
}
```

## 请求规范

- 所有接口统一使用 HTTP POST，请求体为 JSON。
- 接口版本固定为 `2021-03-23`。
- `Region` 为必填公共参数，默认使用 `ap-guangzhou`。

请求示例：

```
POST / HTTP/1.1
Host: aca.tencentcloudapi.com
Content-Type: application/json; charset=utf-8
Authorization: TC3-HMAC-SHA256 Credential=.../tc3_request, SignedHeaders=content-type;host, Signature=...
X-TC-Action: MatchDrug
X-TC-Version: 2021-03-23
X-TC-Timestamp: 1716630000
X-TC-Region: ap-guangzhou

{"Drugs":[{"DrugName":"诺氟沙星片"}],"DrugType":0}
```

## 调用工具

使用 `scripts/aca_rational_drug_client.py` 封装签名和调用逻辑：

```bash
python scripts/aca_rational_drug_client.py <Action> \
  --config ~/.config/medication-advisor/aca.json \
  --payload-json '<JSON>'
```

调试时加 `--dry-run` 可打印请求结构而不实际发送。

## 接口列表

| 接口名 | 功能 |
|--------|------|
| `MatchDrug` | 药品名标准化，返回 `DrugHashId`、`Similarity` |
| `MatchDiagnosis` | 诊断标准化，返回 `ICDCode`、`StandardName` |
| `MatchFrequency` | 用药频次标准化，返回 `StandardCode`、`DailyTimes` |
| `MatchRoute` | 给药途径标准化，返回 `StandardCode`、`StandardName` |
| `QueryInteractionRisk` | 多药相互作用/配伍禁忌查询，需传入标准药品 ID |
| `QueryAdverseReactionRisk` | 不良反应风险查询，需传入标准药品 ID |
| `ReviewRationalDrugUse` | 综合处方审核（9 大维度），需传入患者、诊断、处方信息 |

详细字段定义和示例见各接口文档及 `references/aca-2021-03-23/数据结构.md`。

## 使用限制

- `MatchDrug` 单次最多传入 10 个药品。
- `Similarity < 0.7` 时不使用匹配结果，后续依赖标准药品 ID 的接口（`QueryInteractionRisk`、`QueryAdverseReactionRisk`、`ReviewRationalDrugUse`）跳过，改用大模型兜底。
- 对用户输出时只说明结论和注意事项，不展示原始 JSON、接口名或内部字段。
