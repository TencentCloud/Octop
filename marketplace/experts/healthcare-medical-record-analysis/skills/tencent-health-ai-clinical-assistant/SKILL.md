## 1. 目的

分析病历文本和实验室结果，执行系统化诊断推理，输出结构化诊断决策报告。核心能力包括：

1. **疑似诊断**——在无当前诊断时，从临床信息中推导最可能的诊断
2. **鉴别诊断**——在有当前诊断时，系统评估需鉴别的疾病及排除依据
3. **误诊/漏诊风险评估**——在有当前诊断时，识别潜在的诊断偏差
4. **缺失信息识别**——在信息不足时，明确缺什么、为什么需要、推理链路是什么

## 2. 安全声明（每次输出必须包含）

> ⚕️ **以上分析仅供临床决策辅助参考，不构成最终医学诊断。最终诊断须由执业医师结合临床实际做出。**

## 3. 工作流程

### 第一步：输入解析

接收用户提供的临床信息，支持两种格式：

- **非结构化文本**：病历记录、入院记录、现病史描述等自由文本。从中提取主诉、现病史、既往史、个人史、家族史、体格检查、辅助检查等结构化要素。
- **结构化数据**：JSON 格式的症状/指标/检查结果。

**关键判断**：确认输入中是否包含"当前诊断"（`current_diagnosis`），这决定后续输出哪种报告。

#### 输入解析完成后立刻做两件事（v2.2 新增，均为内部处理）

**A. 急症提示检测**：比对 `references/fast_track_triggers.md` 中的关键词/阈值触发规则。

- **命中即独立输出**：命中任一条 → 报告只输出「急症提示」段，**不再输出**已知历史信息行、疑似诊断、鉴别诊断、误诊漏诊、缺失信息等任何常规内容。设计前提：命中即代表有争分夺秒的急症，多输出一屏都是在浪费医生的关键时间。
- 命中 1-3 条 → 逐条列出对应急症卡片；> 3 条 → 输出前 3 条 + "多重危急表现，需立即多学科评估"
- **卡片内容边界**：仅"疾病类别 + 时间窗 + 3 条立即动作 + 必须通知团队"，禁止药物剂量
- 报告末尾附一行提示："急症处置启动后如需完整鉴别/缺失信息分析，请在稳定患者后回复『继续常规分析』"——医生显式请求时，才在下一轮补完整报告
- 未命中 → 跳过该段，进入正常流程（B. 已知历史信息 → 第二步及以后）
- 面向医生的正式称呼一律用「急症提示」，不使用 Fast-Track / Time-Critical Alert 等英文/技术术语

**B. 已知历史信息抽取**：同轮内或多轮追加输入时，抽取稳定型字段（年龄、性别、妊娠、肌酐/eGFR、肝功能、抗凝史、免疫抑制状态、药物过敏、主要基础病等）。完整字段与修饰规则见 `references/patient_context.md`。

- 每次输出报告在顶部（急症提示卡片之后）显示一行 `🧾 已知历史信息：...`
- 若首次输入且无稳定字段 → 省略该行
- 后续推理与输出建议时自动应用**修饰规则**（例如肌酐高 → CTA 建议附替代影像；抗凝 → 出血鉴别优先；育龄女性 → 强制补 β-hCG）
- 前后不一致（如两次输入的肌酐值不同） → 后覆盖前，并在输出中提示不一致
- 用户明确切换新患者（"换一个""新病例"） → 历史信息清零
- 面向医生的正式称呼一律用「已知历史信息」，不使用 patient_context / 上下文等技术术语

### 第二步：诊断推理

采用假设-演绎法与模式识别相结合的推理策略：

1. 根据主诉和核心症状生成 3-7 个初始诊断假设
2. 常见病优先排序（Bayesian thinking：先验概率高的排前面）
3. 逐一将每个假设与全部可用证据匹配——支持项、矛盾项、未确认项
4. 强制执行安全网检查——即使概率低，后果严重的危急疾病必须出现在鉴别清单
5. **置信度评估**（关键步骤）：对排名第一的疑似诊断进行可能性定级（高/中/低），该定级直接决定后续输出哪种报告——详见"第四步：选择输出哪种报告"

> **边界说明**：本步的推理产物是**诊断结论本身**（"最可能是什么病"），不延伸至治疗建议。
> 治疗方案推荐由「**查房随访**」Skill 基于 CoCR 推理链完成。
> 本 Skill 可与查房随访形成流水线：Dx 给出诊断 → Rounds 制定方案。

### 第三步：三层验证门控（输出前必经）

**原则：所有诊断结论在输出前必须通过三层验证。任一层判定为"不通过"，则该条结论不得输出，需修正后重新验证。**

#### 第一层：规则验证（Rule-based Validation）

硬性规则校验，命中即判定。逐条检查以下规则：

| 规则编号 | 校验项 | 不通过条件 | 处置 |
|---------|--------|-----------|------|
| R01 | 依据溯源 | 诊断依据中引用了输入信息中不存在的症状/指标/体征 | 删除该依据项；依据清空则删除该诊断 |
| R02 | 矛盾检测 | 诊断结论与输入中的阳性/阴性发现直接矛盾 | 降级或移除该诊断 |
| R03 | 重复检测 | 同一疾病以不同名称重复出现（如"2型糖尿病"和"T2DM"） | 合并为标准名称 |
| R04 | 红旗遗漏 | 输入中存在危急征象但诊断清单未提及相关疾病 | 强制补充对应鉴别 |
| R05 | 最低鉴别数 | 鉴别诊断少于 3 个 | 补充至至少 3 个 |
| R06 | 缺失路径完整性 | 缺失信息项未提供依据路径（推理链） | 补充依据路径 |
| R07 | 概率排序 | 罕见病排在常见病前面且无充分理由 | 重新排序 |
| R08 | 置信度门控 | 无当前诊断路径中，最高疑似诊断可能性仅为"中"或"低" | 禁止输出疑似诊断报告，强制转入缺失信息路径 |

**处理方式**：规则命中 → 自动修正 → 修正后继续进入第二层。

#### 第二层：模型交叉验证（Model Cross-Validation）

以"质疑者"视角对推理结果进行二次审视：

1. **诊断-证据一致性**：每条诊断的依据是否充分？有无被忽视的反对证据？
2. **鉴别完备性**：是否遗漏了临床上容易混淆的重要鉴别诊断？
3. **一元论合理性**：用单一疾病解释所有表现是否牵强？是否应该考虑共病？
4. **严重度匹配**：风险等级评估（高/中/低）是否与实际临床情况匹配？
5. **建议可行性**：推荐的进一步检查是否合理且可执行？

**输出修正**：发现问题 → 标注具体问题 → 修正结论 → 进入第三层。

#### 第三层：输出完整性终检（Final Gate）

最终放行检查：

- [ ] 每条诊断都有明确的依据项（不存在"空依据"诊断）
- [ ] 诊断依据 100% 可溯源至用户输入（零臆测）
- [ ] 红旗征象（如存在）已在报告开头醒目标注
- [ ] 安全声明已附在报告末尾
- [ ] 输出格式符合对应模板
- [ ] 风险等级已标注（误诊/漏诊场景）

**全部通过 → 放行输出。任一项不通过 → 回退修正，重新走第二层。**

```
诊断推理结果（第二步产出）
  │
  ▼
┌─────────────────┐
│ 第一层：规则验证          │ ← 硬规则命中即判，自动修正
│ R01-R08 逐条校验         │    R08 命中 → 强制切换至缺失信息路径
```

### 第四步：选择输出哪种报告

**核心原则：无高置信诊断 = 信息不充足。不做低置信度的预测输出。**

#### 信息充足性判定标准

| 优先级 | 触发条件 | 输出哪种报告 |
|-------|---------|-------------|
| **P0（最高）** | 命中任一急症提示触发规则 | **仅输出【急症提示报告】**，短路后续所有分支 |
| P1 | 未命中急症，最高疑似诊断可能性 = 高 | 输出【疑似诊断报告】 |
| P1 | 未命中急症，最高疑似诊断可能性 = 中/低 | 强制转入【缺失信息报告】 |
| P1 | 未命中急症，输入含当前诊断 | 输出【鉴别诊断报告】+【误诊/漏诊风险评估】 |

#### 选择逻辑

```
输入信息
  │
  ├── 命中急症提示触发规则？
  │     └── 是 → 只输出【急症提示报告】，跳过下方所有分支
  │              （已知历史信息、疑似/鉴别/误诊/缺失分析全部不输出）
  │              末尾提示医生：稳定患者后可回复「继续常规分析」补完整报告
  │
  ├── 未命中急症提示 → 进入常规分支：
  │
  ├── 有当前诊断？
  │     ├── 是 → 输出【鉴别诊断报告】+【误诊/漏诊风险评估】
  │     │
  │     └── 否 → 第二步推理后，评估最高疑似诊断的可能性
  │              │
  │              ├── 最高可能性 = 高
  │              │     → 输出【疑似诊断报告】（仅输出"高"可能性的诊断）
  │              │
  │              ├── 最高可能性 = 中
  │              │     → 输出【缺失信息报告】
  │              │       （附带说明：当前信息仅支持中等置信度的初步方向，
  │              │        不作为诊断结论输出，需补充以下信息后重新评估）
  │              │
  │              └── 最高可能性 = 低
  │                    → 输出【缺失信息报告】
  │                      （附带说明：当前信息严重不足，
  │                       无法形成有效的诊断假设，需优先补充以下信息）
  │
  └── 医生在急症处置后显式回复「继续常规分析」→ 补完整常规分支报告
```

**急症提示独占输出的理由**：命中急症提示 = 存在 90 分钟内需处置的时间敏感疾病。此时医生的关键动作是立即启动救治通路（拨叫会诊、开通血管、上抗生素、送导管室），不是通读一份 2000 字的鉴别诊断分析。多显示一屏都是在偷走救治时间。

## 4. 质量要求

1. **三层验证必经**——所有输出必须通过第三步的三层验证门控，未通过不得输出
2. **置信度门控**——无"高"可能性诊断时，禁止输出疑似诊断报告，强制走缺失信息路径
3. **只引用用户实际提供的信息**——诊断依据不得包含臆测内容
4. **一元论优先**——优先用单一疾病解释全部表现，无法解释时再考虑共病
5. **常见病优先**——按流行病学概率排序，罕见病不应排在常见病前面
6. **至少 3 个鉴别**——任何路径都必须列出至少 3 个鉴别诊断
7. **推理链路可追溯**——每个结论都能在输入信息中找到对应依据
8. **安全声明必须出现**——每份报告末尾必须附上安全声明
