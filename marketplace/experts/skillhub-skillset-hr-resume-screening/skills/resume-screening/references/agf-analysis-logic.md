# AGF 底层分析逻辑（简历 / 面试通用判定参考）

> 用途：配合 `resume-screening` skill 使用。分析候选人时，用这套逻辑把简历信号和面试回答映射到 AGM 层级，判断「这个人现在能承担什么复杂度」。
> 本文件只含分析逻辑，不含任何员工画像，也不含任何公司专属口径（学历门槛、否决项等由使用者在自己的 Job Card 里自定义）。

---

## 〇、核心心法（判人之前先记住）

**AGF 不识别天才，AGM 是 GPS 定位**。目的是判断「他现在能承担什么复杂度」，不是给人贴好/坏标签。

```
层级不会消灭问题。层级只是改变你解决的问题类型。
L1 解决"我不会"
L2 解决"流程不对"
L3 解决"系统不存在"
L4 解决"组织为什么持续产生这个问题"
```

**判定铁律**：
1. **只看行为证据，不看自我评价**——"我觉得我优化能力挺强"不是证据，一次具体的事才是
2. **判断可能信息不足，不是能力不够（P8）**——他答不上来，可能只是没见过/不会表达
3. **回答质量好 ≠ 层级高**——说得好但没做过，降一级标注"认知到位"
4. **岗位 title ≠ 层级**——永远不看 title，只看行为

## 一、AGM 层级体系（12 格判定核心）

> 4 级 × 3 段 = 12 格。判层级先落格，再落段。

### L1 — 执行者（解决"我不会"）

| 段位 | 特征 | 判定标准 |
|:---:|------|---------|
| L1.1 依赖执行 | 需要明确指令才能行动 | "今天没人安排我就不知道做什么" |
| L1.2 独立执行 | 拿到任务能独立完成，可靠 | "交给我你放心" |
| L1.3 精进执行 | 完成 + 开始识别规律，偶尔提改善建议 | "这个事做了三次了，我觉得可以这样更快" |

### L2 — 优化者（解决"流程不对"）

| 段位 | 特征 | 判定标准 |
|:---:|------|---------|
| L2.1 被动优化 | 出问题后才优化（犯错→改习惯→建检查） | "上次搞错了，现在我每次都核对" |
| L2.2 主动优化 | 没出问题也找优化空间，建个人工具/方法 | "虽然没错过，但我觉得可以更快" |
| L2.3 模式优化 | 在一类问题里看到共同模式，消灭一类问题 | "不止这一件事，这类问题我都统一处理了" |

### L3 — 系统建设者（解决"系统不存在"）

| 段位 | 特征 | 判定标准 |
|:---:|------|---------|
| L3.1 域内建系统 | 职能域内建可复制的流程/工具/SOP | "我们财务的 billing 流程不会再出错了" |
| L3.2 跨域建系统 | 跨部门推动别人也用你建的东西 | "不只是财务，仓库那边也开始用这个流程了" |
| L3.3 培养建系统者 | 教会别人如何建系统（乘法效应） | "我不在的时候，他们自己也能建流程了" |

### L4 — 组织设计者（解决"为什么持续产生这个问题"）

| 段位 | 特征 | 判定标准 |
|:---:|------|---------|
| L4.1 自我升级 | 更新认知模型，开始把组织当对象思考 | "以前怪人→现在调系统→想为什么组织一直产生这类问题" |
| L4.2 组织升级 | 团队/部门因你设计的系统改变，不再依赖你 | "有人也开始说'先看流程别怪人'，且不是因为你要求的" |
| L4.3 生态升级 | 培养出 L3 且 L3 在培养新 L3 | 你不在，组织照常生长 |

### 层级速记（一句话）

- **L1** 自己 → **L2** 工作/流程 → **L3** 系统 → **L4** 组织
- 同一句话三种层级（面试听答案时直接套）：
  - "我每天都核对" = L1.3-L2.1（有动作）
  - "我做了个表格，现在都是我自己查" = L2.2（个人工具）
  - "我做了个表，现在同事都用它查，不用再来问我" = L3.1（别人在用）

## 二、8 维观测维度（看什么）

> 分析任何人的回答，从这 8 个维度切。每个维度找 1 个行为证据即可定局部。

| # | 维度 | 观测点 |
|:---:|------|--------|
| ① | Problem Solving | 遇到问题的第一反应：找人 / 自己研究 / 找根因 / 建流程 |
| ② | Learning | 学习偏向：实践 / 阅读 / 请教 / 模仿 / 总结 |
| ③ | Error Handling | 面对错误：隐藏 / 解释 / 承担 / 复盘 / 流程优化 |
| ④ | Repetition | 面对重复：接受 / 提速 / 自动化 / 流程化 / 重新设计 |
| ⑤ | Collaboration | 协作偏好：独立 / 协作 / 协调 / 培养别人 / 跨部门 |
| ⑥ | Growth | 是否改变过去观点 / 主动升级自己 / 接受反馈 / 持续迭代 |
| ⑦ | Motivation | 驱动力：挑战 / 稳定 / 收入 / 成就 / 影响力 / 成长 |
| ⑧ | Value | 价值排序：责任 / 原则 / 效率 / 创新 / 团队 / 客户 |

## 三、行为证据判定（怎么判）

### 有效证据（可以用于判定）

| 类型 | 示例 | 可判定什么 |
|------|------|----------|
| 具体案例 | "之前给客户发错了报价表，后来每个客户都改专属文件名，发送前核对三遍" | L2.1 被动优化 |
| 可追溯的结果 | "billing 从每月出 3 次错到现在半年 0 差错" | L3.1 域内建系统 |
| 别人的变化 | "现在仓库那边也开始用我建的核对流程了" | L3.2 跨域建系统 |
| 原话对比 | "以前我觉得是人的问题，现在会先看流程哪里不对" | L4.1 认知跃迁 |
| 具体人物+行为 | "小王以前每次都问我怎么报价，现在她自己用我写的表独立报了三份" | L3.3 培养建系统者 |

### 无效证据（不能用于判定）

| 类型 | 示例 | 为什么 |
|------|------|-------|
| 自我评价 | "我觉得我优化能力挺强的" | 无行为支撑 |
| 包装式回答 | "同事提建议是对我的认可" | 回避具体问题 |
| 模糊描述 | "我改进了工作流程" | 没说怎么改、效果怎样 |
| 未来承诺 | "我准备下一步做自动化" | 还没做 |
| 单字/极短回答 | "有。" | 信息密度不够 |
| 观点而非行为 | "我认为细心很重要" | 价值观不是行为 |

### 判定的核心三问（L3 及以上必问）

1. **别人在用吗？**（≥2 人依赖它工作）
2. **离开创造者能运转吗？**（有文档/模板/操作纪律，不是靠"问他"）
3. **消灭了重复劳动吗？**（以前每次手动做，现在不需要了）

> **不问工具形态**：Excel 宏 + 共享盘 + 操作流程 = 系统（L2.8）；微信 + 文档模板 + 执行纪律 = 平台（L3.0）。系统建设信号 ≠ 技术建设。

## 四、快速判定表（看到行为 → 直接判）

| 你看到的行为 | 直接判定 |
|------------|:---:|
| 说不出任何独立完成的任务 | L1.1 |
| 说了任务但说不出具体步骤和结果 | L1.1（待验证） |
| 独立完成任务 + 说不出任何改善建议 | L1.2 |
| 独立完成 + 至少提过 1 次具体建议 | L1.3 |
| 有犯错后建习惯的具体案例 | L2.1 |
| 有未出错就主动优化的案例 | L2.2 |
| 优化消灭了一类问题 + 有结果 | L2.3 |
| 建了流程/工具 + 别人在用 + 有名称 | L3.1 |
| 建的东西被跨部门使用 + 能说出谁在用 | L3.2 |
| 培养的人独立建了新系统 + 能说出具体案例 | L3.3 |
| 有认知跃迁原话 + 以前vs现在对比清晰 | L4.1 |
| 有别人因为你改变认知的原话证据 | L4.2 |
| 有外部可验证的组织级变化证据 | L4.3 |
| 说得好但无行为案例 | **降一级，标注"认知到位"** |
| 行为模糊（无时间/人物/结果） | **维持层级，标注"证据模糊"** |
| 追问后仍无具体案例 | **相关维度不纳入判定** |

## 五、防误判过滤器（判层前必查）

### P8：信息面 vs 能力面（第一过滤器）

> 结论可能是信息不足，不是能力不够。

```
判层前必问：
这个人的结论/行为，有没有可能是因为他没看到全貌？
如果信息补全了，他还会是这个结论吗？
如果不会 → 不是能力问题 → 补信息面，不是教能力
```

### P9：Gate 全否定 ≠ L1（防漏规则）

> 一个人回答全是"没有"/"无"/"独立完成"，不代表能力 L1。可能是不会表达。

```
Gate/面试 ≥4 题否定回答 → 不判 L1 → 必须用具体场景问题逼出真实能力
（"你上次遇到 X 情况怎么做的"比"你有没有优化过"更能测出真实水平）
```

### 角色基准偏靠（不同岗位不同基线）

| 角色 | 基线 | 加分项 |
|------|------|--------|
| PM/产品 | 方法论描述是基本面（L2 基线） | L3 需外部验证证据（别人用过） |
| IT/测试 | L2 基线（独立完成任务） | 建了系统 → L2.5+；系统被跨域采纳 → L3 |
| 客服/财务/行政 | 表达弱于行动 | 有实战数字是强信号，不看表达包装 |

### 常见判定陷阱

1. **回答质量好 ≠ 层级高**——认知和行为差距，以行为定层级，认知作为"潜力"标注
2. **岗位 title ≠ 层级**——不看头衔，只看行为证据
3. **一次好回答 ≠ 稳定层级**——多个维度交叉验证，只有一个维度达标 → 整体降半级
4. **第一次犯错后改 ≠ L2.1**——要看到"错误处理模式"，不是单个错误后的反应
5. **建了东西但没人用 ≠ L3**——L3 核心标准是"别人在用"，不是"我建了"

### 单次不升级规则

> 信任类/人格类问题（说谎/推责/归因外部）：**单次事件按"状态"记录，不定性、不面谈；同类 ≥2 次才升级。** 一次样本不足以定人格。

## 六、Growth Blocker（反成长风险 B1-B7）

> 判断一个人"为什么成长停了/退了"用这套。B 是诊断，不是标签。

| # | Blocker | 表现 | 修复方向 |
|:---:|------|------|---------|
| B1 | 能力不足 | 任务超出层级太多，反复失败 | 回退一步，打牢基础 |
| B2 | 信息面不足 | 判断片面，看事情只有一个角度 | 拉通信息源，让他看全貌 |
| B3 | 资源不足 | 想优化但没权限/预算/工具 | 给工具或给权限，先给一样 |
| B4 | 负载过高 | 长期救火，从主动优化退化为被动响应 | 降负，先卸一件事 |
| B5 | 激励不匹配 | 做了优化没反馈，逐渐不做了 | 给反馈、给署名、给使用权 |
| B6 | 环境限制 | 岗位边界太窄，没有跨域机会 | 扩展职责边界或轮岗 |
| B7 | 权限被收回 | 曾经的自主权被收走，退回执行 | 确认是否可逆，不可逆考虑换岗 |

## 七、应用到简历 / 面试（resume-analysis 怎么用）

### 简历阶段：只能判"信号层"，不能判"能力层"

- 简历写出的 → 显性信号（L1.5-L2.2 可给，高如 L2.2 需面试确认）
- 简历没写但结构暗示的 → 待验证信号
- 无证据的维度 → "无法判定"，不猜
- **置信度封顶 55%**（面试前）/ 70%（面试后）

### 面试阶段：把回答转成行为证据再判

```
听到回答 → 提取行为证据（有效/无效表）→ 套快速判定表 → 落 12 格
追问模板：
  "当时什么情况？你负责哪部分？具体做了什么？结果怎么度量？"
  "现在还有人用吗？"（验 L3）
  "如果信息补全了，你的判断会变吗？"（验 P8）
```

### 候选人分型对判定的影响

| 分型 | 判定策略 |
|------|---------|
| 应届生（毕业 ≤1 年） | 无经历可验 → 看萌芽信号（学习能力、主动性、第一反应），大部分维度"待验证" |
| 已工作（毕业 ≥1 年） | 有经历可验 → 经历真实性、成果个人占比是重点，可抽 L 层信号 |
| 教育年限异常应届 | 属应届分型，教育经历有省略/年限异常 → 多挖一层缺失段（上进心 + 那段做了什么） |

## 附：面试题与层级的对应关系（出题参考）

| 想验证什么 | 面试题方向 | 对应层级信号 |
|------|------|------|
| 会不会独立做事 | "讲一个你独立完成的任务，从头到尾" | L1.2-L1.3 |
| 会不会发现问题 | "有没有哪件事本来可以更好，你主动改掉了？" | L2.2 主动优化 |
| 会不会消灭一类问题 | "有没有反复出现的问题，你怎么处理的？" | L2.3 模式优化 |
| 会不会建系统 | "你建过什么别人还在用的东西？谁在用？" | L3.1（验"别人在用"）|
| 会不会带人建系统 | "你带的人里，有没有人能独立建东西了？" | L3.3 |
| 会不会升级认知 | "有没有以前坚信、现在推翻的观点？" | L4.1 |
| 有没有方向 | "你对自己 2-3 年后的预期？" | 驱动/时间尺度 |
