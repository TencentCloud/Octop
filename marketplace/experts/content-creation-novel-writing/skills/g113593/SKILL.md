# Tomato Novelist：番茄小说分章创作

## 三条铁律

1. **正文落文件。** 每章写进 `novels/<书名>/第NNN章.md`；对话里只给摘要和 `文件:行` 指针，禁止把整章正文粘进消息。
2. **前 20% 定生死，最后 5% 定追读。** 开头必须有即时冲突，结尾必须有钩子。没有钩子的章节不值得存在。
3. **字数按频道定，而且它只是信号。** 默认 2200-2500 字，男频用 `--preset male` 放宽到 2500-3000。够不到下限时缺的是**事件**不是描写——注水直接杀完读率。

## 第一阶段：6 问锁定爆款基因

用提问工具**一次问完**（不要一条条打字），结果记录到项目 `00-大纲.md` 的「作品基因」区：

| # | 问题 | 选项（可自定义） |
|---|---|---|
| 1 | 情绪标签（决定算法推荐） | 打脸爽文 / 极致虐恋 / 爆笑反套路 / 悬疑惊悚 / 治愈甜宠 / 脑洞大开 |
| 2 | 题材 | 悬疑推理 / 现代言情 / 古代言情 / 奇幻玄幻 / 科幻未来 / 武侠仙侠 / 历史架空 / 都市现实 |
| 3 | 主角 | 男主独角戏 / 女主独角戏 / 双主角 / 群像 |
| 4 | 核心反差点 | 扮猪吃虎 / 马甲掉落 / 被虐觉醒反杀 / 老实人黑化 / 隐藏大佬装萌新 / 废柴天赋异禀 |
| 5 | 核心冲突 | 生死存亡 / 查明真相 / 爱情阻碍 / 复仇雪恨 / 权力争夺 / 成长突破 / 守护保护 |
| 6 | 目标总字数 | 8 万（≈32 章，刚过门槛，建议留余量）/ 15 万（≈60 章）/ 30 万（≈120 章）/ 100 万+（≈400 章）/ 自定义 |

第 3 问之后顺带追问一句主角的职业/身份即可。

**第 6 问的硬约束**：番茄长篇的签约门槛与分发门槛是两道坎——首签门槛较低（2 万字量级），但要让作品进入平台正常分发需要更多字数。2 万–8 万之间基本是“分发洼地”，写了也拿不到量，**不要抱着“先写 10 章试试”做长篇**。具体数字会随平台规则变，**以番茄作家助手后台的当前规则为准**。用户给的是总字数，按**区间上限**换算章节数（默认 ÷2500，男频 ÷3000）。

**单章字数基线**：

| 频道 | 单章字数 |
|---|---|
| 默认（女频 / 双主角 / 群像 / 还没定） | 2200-2500 |
| 男频（战神 / 赘婿 / 系统 / 玄幻） | 2500-3000 |

> 判据是**目标读者频道**（男频 / 女频），不是主角结构：双主角或群像同样可以是男频（战神 / 系统 / 玄幻），这种就加 `--preset male`。女频与默认同档，不用加参数。
> 番茄靠**完读率**分发，章越长越难读完，所以默认档比男频档更短。

## 第二阶段：规划五件套

在 `novels/<书名>/` 下建：

1. `00-大纲.md` — 用 `templates/大纲.md`
2. `01-人物档案.md` — 用 `templates/人物档案.md`
3. `02-情绪曲线.md` — 用 `references/番茄情绪曲线.md` 的 3 章节奏模板铺满本卷
4. `03-黄金开篇.md` — 按 `references/章节引擎.md` 的「黄金开篇 50 字」出 3 个版本（强冲突 / 强反差 / 强情绪）
5. `00-大纲.md` 的「文风锚点」区 — **用本书的目标文风写一段 200 字典型段落，必须含一段对话 + 一段动作**，给用户确认后**只冻结这一区（200 字样段本身），此后不许改**；`00-大纲.md` 的其余区段照常更新

五项做完，向用户展示规划摘要并等确认，确认后再开写。

> 文风锚点是去 AI 味最强的单一杠杆：规则只能枚举“不许写什么”，样本能同时约束节奏、用词和标点习惯。**跳过它，后面每章的润色都失去基准。**

## 第三阶段：逐章创作（12 步，不跳步）

1. 读 `00-大纲.md`（本卷摘要 + 近 5 章细摘要 + 本章细纲），把本章标为「进行中」
2. 读上一章正文的**结尾三段**，确认钩子接力
3. 读 `02-情绪曲线.md`，确认本章在 3 章单元里的情绪任务
4. 设计开头：前 20% 必须落进 `references/章节引擎.md` 的「十种开头式」之一
5. 排场景：≤2500 字排 2-3 场，>2500 字排 3-4 场，至少 1 场带本章情绪标签
6. 写正文到 `第NNN章.md`，用 `references/章节模板.md` 骨架，字数按频道基线；**必须保留 `## 正文` 小节**，脚本靠它界定统计范围
7. 设结尾钩子：从「十种结尾钩子」里选，且与上一章**不同类型**
8. 连贯性自查：人物行为符合档案？上一章悬念有回应？时间线没跳错？
9. 去 AI 味：**先对着「文风锚点」逐句改 → 再逐条过 `references/文风与去AI味.md` 的对照表与禁用词表 → 最后跑脚本机检；机检若还有命中，回到第一步再改一遍**
10. `python scripts/check_chapter_tomato.py 第NNN章.md [--preset male]` — 一次查出字数和 AI 味痕迹，改到字数达标、AI 味清零（少数命中可确认保留）。脚本统计的是**不含标点的汉字数**，是平台字数的**下界**。**低于下限先查「本章是否缺一个核心事件/一场冲突」，补事件而不是补描写；高于上限先砍重复信息，不要砍钩子。**
11. 过 `references/交付前必查.md` 的 12 项硬门槛，有不过的先改
12. 收尾：`00-大纲.md` 写本章记录（100-200 字摘要 + 实际情绪曲线 + 评论区争论点预测）并标「完成」，同时**登记本章新埋的伏笔、给已回收的销账**；`02-情绪曲线.md` 登记本章钩子类型；`01-人物档案.md` 更新状态快照
    - 每满 5 章，在这一步加做一次数据体检：问用户完读率 / 追读率 / 评论关键词，据此改后续大纲

**每 3 章走完一次「压-小扬-压-爆」，每 5 章做一次节奏体检。**

### 确认节奏

默认**连写 3 章再确认**（用户要求每章确认时照办）。每批结束汇报：本章摘要、实测字数、AI 味命中数、钩子类型、下批走向。每 5 章问一次真实数据（完读率 / 追读率 / 评论关键词），据此改后续大纲——给高人气配角加戏，强化已经跑通的情绪标签。

## 长篇管理

- **大纲分卷归档。** `00-大纲.md` 只留「本卷摘要 + 近 5 章细摘要 + 全部未回收悬念」；写完一卷，把该卷摘要压成一行（卷号 + 一句话主线 + 关键转折 + 本卷字数）挪进 `00-大纲-卷摘要.md`（**第一卷收尾时新建，之后只追加**），本文件对应段落删掉。不归档的话，第 200 章时大纲自己就有几万字，而且每章都要重读一遍。
- **悬念线追踪表。** 每埋一个伏笔登记一行，回收了销账。连续 10 章没回收的，当章回收或直接删。
- 人物状态每 10 章冻结一次快照，防人设悄悄漂移。

## 底线

- 不写：违法内容、色情内容、暴力煽动、未授权 IP 续写。涉及真实人物或真实事件时，主动提示名誉与事实风险。
- 用户说「你直接写，别问」时：跳过 6 问的逐项确认，用合理默认值直接开工；文风锚点自行拟好后标为「待确认（草稿冻结）」，用户首次反馈时可改一次。但**文件落盘、字数与 AI 味机检、交付前必查照做**。
